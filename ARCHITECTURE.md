# ARCHITECTURE.md — TrustVault System Architecture

## Overview

TrustVault is a secure enterprise document management system built for the Snovasys Fresher Hiring Challenge 2026. It provides role-based document storage, fine-grained access grants, and tamper-evident audit logging.

## System Diagram

```
┌──────────────────────────────────────────────────────────────┐
│                        Browser (React)                        │
│  Login → Dashboard → Document Library → Upload/View/Edit     │
│  Permission Management → Audit History → Admin Dashboard     │
└──────────────────────┬───────────────────────────────────────┘
                       │ HTTPS (JWT in Authorization header)
┌──────────────────────▼───────────────────────────────────────┐
│              Supabase Edge Functions (Deno)                   │
│  /upload  /download  /delete  /grant  /revoke  /audit        │
│  All functions: verify JWT → check RLS → execute → log       │
└──────┬─────────────────────────────────────────┬─────────────┘
       │                                         │
┌──────▼──────────┐                    ┌─────────▼──────────┐
│  PostgreSQL DB   │                    │  Supabase Storage   │
│  (Supabase)      │                    │  (private bucket)   │
│  RLS Enabled     │                    │  No public access   │
└──────────────────┘                    └────────────────────┘
```

## Database Schema

### Tables

#### `profiles`
Stores user profile and role information.
- `id` UUID PK (references auth.users)
- `email` TEXT
- `role` TEXT CHECK (administrator | owner | viewer)
- `created_at` TIMESTAMPTZ

#### `documents`
Document metadata. Actual files stored in private Supabase Storage.
- `id` UUID PK
- `owner_id` UUID FK → profiles(id)
- `title` TEXT NOT NULL
- `description` TEXT
- `file_path` TEXT NOT NULL (storage path)
- `file_name` TEXT NOT NULL
- `file_size` BIGINT
- `mime_type` TEXT
- `version` INTEGER DEFAULT 1
- `created_at` TIMESTAMPTZ
- `updated_at` TIMESTAMPTZ

#### `document_grants`
Explicit per-document access grants.
- `id` UUID PK
- `document_id` UUID FK → documents(id)
- `granted_to` UUID FK → profiles(id)
- `granted_by` UUID FK → profiles(id)
- `permission` TEXT CHECK (read | edit)
- `created_at` TIMESTAMPTZ
- `expires_at` TIMESTAMPTZ (optional)

#### `audit_logs`
Append-only audit trail. No UPDATE or DELETE permitted.
- `id` UUID PK
- `actor_id` UUID (who performed the action)
- `action` TEXT (upload | download | delete | grant | revoke | login | denied)
- `resource_type` TEXT (document | grant)
- `resource_id` UUID
- `metadata` JSONB
- `ip_address` TEXT
- `created_at` TIMESTAMPTZ

## Row-Level Security Policies

### `documents` table
- SELECT: owner_id = auth.uid() OR admin OR EXISTS(grant for viewer)
- INSERT: authenticated users only (owner_id set to auth.uid())
- UPDATE: owner_id = auth.uid() OR admin OR edit-grant EXISTS
- DELETE: owner_id = auth.uid() OR admin

### `document_grants` table
- SELECT: owner or admin or granted_to = auth.uid()
- INSERT/UPDATE/DELETE: owner_id of document OR admin

### `audit_logs` table
- SELECT: admin sees all; owner/viewer see only their own
- INSERT: service role only (via Edge Functions)
- UPDATE: NONE
- DELETE: NONE

## Storage Architecture

- Bucket: `documents` (private, RLS enforced)
- File path: `{owner_id}/{document_id}/{filename}`
- Downloads: short-lived signed URLs (60 seconds) generated by Edge Function after permission check
- No public URLs ever issued

## Authentication Flow

1. User signs in via Supabase Auth (email/password)
2. JWT issued, stored in Supabase client session
3. Frontend sends JWT in `Authorization: Bearer` header to Edge Functions
4. Edge Functions verify JWT using `supabaseAdmin.auth.getUser(token)`
5. Role resolved from `profiles` table (never trusted from client)

## Edge Functions

| Function | Method | Description |
|----------|--------|-------------|
| `upload-document` | POST | Validates file, stores in private bucket, creates metadata, logs audit |
| `download-document` | GET | Checks current permission, issues 60s signed URL, logs audit |
| `delete-document` | DELETE | Owner/admin only, removes file + metadata, logs audit |
| `grant-access` | POST | Owner/admin grants read or edit to another user |
| `revoke-access` | DELETE | Owner/admin revokes grant, signed URLs expire naturally |
| `update-document` | PATCH | Owner/edit-grant can update metadata or replace file |
| `admin-users` | GET/PATCH | Admin-only: list users, change roles |

## Frontend Routes

```
/                     → redirect to /dashboard or /login
/login               → Login / Register page
/dashboard           → Overview stats + recent activity
/documents           → Document library with search/filter
/documents/upload    → Upload form
/documents/:id       → Document detail + permission management
/shared              → Documents shared with current user
/audit               → Audit log (admin sees all, others see own)
/admin               → Admin dashboard (admin role only)
```
